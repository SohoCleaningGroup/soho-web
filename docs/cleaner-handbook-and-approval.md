# Cleaner handbook and approval email — staging

English handbook: /professional/handbook. Spanish handbook: /professional/handbook/es. Both use the same readable, printable layout with a language switch and contents links; both are noindex. The approval email includes the cleaner's application name in each handbook link, and the pages display it at the top and in the sample introduction. Language switching retains the name. The shared URLs remain generic; the name parameter is display-only, so these links do not grant access to private applicant information. The handbooks contain general team guidance, not applicant/customer information or employment/pay terms.

When an admin changes an applicant to APPROVED, the API atomically claims the status change and sends an English welcome email through the existing SendGrid sender. The email includes links to both English and Spanish handbooks and a private, 30-day hiring-terms signing link; staging uses its Preview branch host, production uses NEXT_PUBLIC_APP_URL. The signer chooses English or Spanish, types the exact application name, checks consent, and signs. The database stores the signed version, full snapshot and SHA-256 hash, name, timestamp, IP, and user agent. A receipt with the signed text is emailed. Admin sees the signature status, and job invitations require it. This draft does not replace the separate pay-rate and protected-leave notices, and each cleaner's individual pay notice remains separate. The $10 quality bonus per qualifying completed job is split equally among assigned cleaners and paid on the first regular payday after SoHo verifies the checklist. Public reviews and missing customer feedback do not determine eligibility. Duplicate status requests do not automatically resend. Other statuses send no welcome email.

The admin view explains the email behavior, shows delivery results, and offers Resend approval email & handbook for approved cleaners. Email failure keeps the admin-approved status and clearly instructs the admin to retry. Approval does not assign a job or capture payment. Existing approved cleaners are not bulk-emailed.

Validation: seven focused tests cover a single approval send, other statuses and unauthorized requests, email failure, explicit approved-only resending, escaped email content, Preview/production links, and parity of handbook sections. TypeScript and focused ESLint passed. Notification tests use mocks; no real cleaner was approved and no actual email was sent during implementation.

## Individual pay notices (2026-10-01)

The approved-cleaner admin page now prepares an individual notice independently of hiring terms. Admin chooses the actual rates, primary language (English or Spanish), effective date, notice reason and preparer, reviews the generated snapshot and explicitly emails a signing link. Spanish-primary-language notices contain both English and Spanish; email framing remains English. Other languages continue to use the linked NY DOL forms manually.

Each notice is immutable after issuance. A new pay change creates a new notice. SHA-256 hashes bind the review, stored snapshot, and acknowledgment; a random 32-byte token is stored only as a hash. Unsigned links expire after 30 days. The cleaner confirms primary language, matches the saved application name, consents and signs. Signing atomically saves name/time/IP/user agent before attempting the receipt email. An email failure preserves the signature; admin can resend the signed copy. Resending an unsigned link replaces its token without changing its text. Signed copies remain printable through their private links. Admin can view and download records. No automatic deletion of notice records is configured; signed records must be retained for at least six years and included in business backups.

The staging-only `CleanerPayNotice` table uses RLS with no public policies and explicitly revokes anon/authenticated access. Server-side admin authentication protects preview/issue/resend/download routes. Public signing is token-scoped, validates origin and size, and rate-limits requests. No analytics run on pay-notice/hiring signing pages, and responses use no-store/no-referrer/noindex headers. Job invitation behavior is unchanged; the admin remains responsible for completing the notice at hiring and before work begins.

Source references: https://dol.ny.gov/notice-pay-rate ; https://forms.labor.ny.gov/WP/LS55.pdf ; https://forms.labor.ny.gov/WP/LS55spa.pdf ; https://www.dol.gov/agencies/whd/fact-sheets/56c-bonuses . Overtime text uses the weighted-average method for multiple rates and notes legally required quality-bonus adjustments. This feature issues notices; it does not calculate or run payroll.

Verification: `node --test scripts/verify-cleaner-pay-notice.cjs`, focused ESLint, TypeScript, staging database atomic-signature/RLS checks, and Vercel preview build. Migration SQL is idempotent so later Prisma deployment can register the already-applied staging table.
